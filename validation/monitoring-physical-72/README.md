# Candidate72 physical monitoring and QIDI print-options test

On 2026-11-06 Dan requested a physical test of the new build and applicable print options. The installed candidate72 submitted a 10×10×4 mm, 20-layer blue ABS cube using the MAX4 0.4 mm nozzle profile, textured PEI, logical T0 mapped to A3, 250°C print / 100°C bed, automatic leveling on and timelapse on. Dan confirmed he does not have the optional polar cooler; it was left off despite the firmware advertising its pin. The actual uploaded executable G-code matched the reviewed GUI export (3,326 executable lines); uploaded archive SHA-256 f7c46dd101ee6d501dc195d3079539d926ad91b3514760e16565d27679263e67.

The printer reported A3 loaded, bed-mesh probe activity, and completed all 20 layers. The camera showed blue deposition and a formed object. Orca showed 0/20 during startup and, after reconnecting, 20/20 while the printer also reported 20/20 (layer-20.png). The initially isolated GUI received SIGTERM (exit 143) while the printer continued; the initiator was not established, so this is not classified as an application crash or a clean exit. The GUI was reopened and reconnected. Printer history reported the job completed; it unloaded to slot16, both heater targets were 0, auto refill remained enabled and polar cooler remained off.

Timelapse was enabled before submission; logs showed successful frame captures and successful rendering. Printer storage contained timelapse_monitor-cube.gcode.3mf_20261106_0635.mp4 (1,374,313 bytes). The setting was restored to its original off state afterward. No refill occurred because only A3 was present; previous A2→A3 tests provide that separate evidence.

Remaining-time estimation did not pass this physical test: candidate72's extrapolation included the printer's preparation time. At layer5 the current formula indicated about 38 minutes despite only roughly 2.6 minutes remaining in this run. A subsequent candidate excludes pre-first-layer time and uses a measured progress baseline, yielding about 2.4 minutes when replayed on these measurements; it still requires its own build and GUI validation. The printer's startup requested 280°C, as in previous tests, and the separate discrepancy remains unresolved. The unsupported polar-cooler option remains a capability-detection issue.
