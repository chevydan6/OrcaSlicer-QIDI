# Orca MAX4 automatic refill test — 2026-11-05

Candidate 70's actual GUI submitted a 30×30×32 mm ABS block with the 0.4 mm MAX4 profile, textured PEI, T0 mapped to A2, bed leveling on, timelapse and polar cooler off. The reviewed GUI export had 250°C print and 100°C bed commands. The printer download and reviewed export had identical executable G-code (47,670 commands); their archive and full G-code hashes differ due to non-executable content. GUI export archive SHA256 9dd5b244147f32ff0463f501605fb441774f1d3fbd690c9b5e034324b9e9c279; printer archive SHA256 d55b80eea39232029bdb4d6afa2c592c5e14636c7a4e69ea6b59eaed65abcc66.

The printer reported Box enabled, value_t0=slot1, auto_reload_detect=1, and matching ABS A2/A3. Dan cut the orange A2 filament on the spool side. At layer 48 the printer automatically paused for refill. The installed firmware fix incremented its correction counter from 1 to 2, retaining logical T0 while choosing slot2/A3, without error. The printer reported slot2 loaded and resumed automatically, without a manual resume. At layer 54 the camera clearly showed blue material on the orange block. Private camera evidence and uploaded archive are retained in research/orca-refill-2026-11-05. The print was still running when this record was written.

This validates the physical A2→A3 case using the existing enabled firmware refill setting and this installed firmware fix. It does not validate an Orca refill enable/disable control, other mappings, multiple Boxes, or unpatched firmware. Startup again targeted 280°C; the separate temperature discrepancy remains unresolved.
